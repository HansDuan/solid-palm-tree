# 真实手写作业照片评测集

把**真实**的手机拍的手写作业照片放这里，再跑 `npm run eval:ocr`，产出的数字才能写进比赛报告。

## 放什么

| 文件 | 必需 | 说明 |
|---|---|---|
| `hw01.jpg` | ✅ | 手写作业照片（手机随手拍即可，别修图——要测的就是真实场景） |
| `hw01.txt` | 推荐 | 人工逐字录入的标准答案，用于算 CER / 要点召回率 |
| `hw01.meta.json` | 可选 | `{"note":"晚自习灯光偏暗","quality":"poor"}` |

建议 **5–10 张**，覆盖不同难度：工整 / 潦草 / 弱光 / 含涂改 / 数学公式 / 代码缩进。

## 怎么跑

```bash
npm run eval:ocr                  # 跑本目录
npm run eval:ocr -- --repeat 3    # 每张跑 3 次，额外得到成功率与稳定性
```

产出：
- 终端逐张明细 + 汇总 + 门槛判定
- `eval/ocr-report.json`（完整数据）
- `eval/ocr-report.md`（可直接贴进作品文档的表格）

## 三个指标怎么读

- **CER（字符错误率）**：转录文本和标准答案的编辑距离占比。≤15% 算可用，手写体 5–10% 就很好。
- **行命中率**：按行对齐的命中比例。批改按「句」取证据，行乱了证据就找错位置。
- **批改要点召回率**：决定分数的关键词（公式、复杂度、术语）保住了多少。**这是对批改准确性影响最大的指标**——CER 稍高没关系，要点丢了才会判错分。

## 红线提醒

- 没有 `HUNYUAN_API_KEY` 时脚本会跑 MOCK 并在报告里标注「模拟数据」——**绝不能把 MOCK 数字当成真实效果写进文档**。
- `.txt` 标准答案必须人工录入，不能拿 AI 转录结果当标准答案（那是自己给自己判卷，数据造假）。
